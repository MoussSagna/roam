# ROAM API — Implementation roadmap

Step-by-step plan of the backend. One step per task: implement, run TypeScript / ESLint / tests, update the docs,
commit, stop for validation. The data sprints (DATA-1 → DATA-8) of
[`DATA_IMPLEMENTATION_PLAN.md`](DATA_IMPLEMENTATION_PLAN.md) run on top of these steps.

## API-02 — Backend foundation — **COMPLETED** (without a database)

Done ([`BACKEND_FOUNDATION.md`](BACKEND_FOUNDATION.md)):

- NestJS 12 app (`@roam/api`, ESM, TypeScript strict) in the pnpm workspace; `build`, `start`, `start:dev`,
  `start:prod`, `typecheck`, `lint`, `test`, `prisma:*` scripts;
- configuration: `@nestjs/config`, environment validated at startup (clear error, no value printed), typed
  `AppConfigService`, `.env.example` with placeholders only;
- Prisma 7: PostgreSQL datasource, `prisma-client` generator, `prisma.config.ts`; `PrismaService` (single client,
  `pg` adapter, startup check, `isReachable`, shutdown) in a global `DatabaseModule`;
- global validation (`whitelist`, `forbidNonWhitelisted`, `transform`), one error filter and format
  (`{ error: { code, message, details? } }`), success envelope (`{ data }`);
- request logging without sensitive data; helmet headers; CORS from `CORS_ORIGINS` (never `*`);
- routing: `/api/v1/...` for domain modules, `/health`, `/health/database`; Swagger on `/docs` outside production;
- 41 tests (Vitest, no database): configuration, CORS, errors, validation, `PrismaService` lifecycle, and the whole app
  over HTTP.

Verified: typecheck, lint, tests, build; the built API started without PostgreSQL (`/health` 200,
`/health/database` 503, Swagger served, CORS, no secret in logs); invalid configuration and production without a
database both stop the startup with one clear line.

**Deferred — waiting for a PostgreSQL environment (not forgotten):**

- real database connection check (`/health/database` → 200, startup "Database connection established");
- migration execution (`prisma migrate dev` / `deploy`) — there is no model to migrate yet anyway;
- database integration tests.

**Deferred to their own steps:** authentication/authorization, rate limiting, domain modules.

### Decisions taken

- NestJS **12** (current major, ESM) rather than 11; Vitest as generated by the NestJS 12 ESM starter; **ESLint** kept
  instead of the starter's oxlint, for consistency with the monorepo.
- Prisma **7** (`7.10`), not the `8.0` release candidate tagged `latest` on npm.
- The API starts without its database outside production (so it runs without a local PostgreSQL); production fails
  fast.
- Health endpoints outside `/api/v1` and outside the `{ data }` envelope (probes read `{ "status": "ok" }`).
- `@scarf/scarf` (telemetry pulled by `swagger-ui-dist`) is denied its install script; `prisma` and
  `@prisma/engines` are allowed theirs (schema engine for migrations) — `pnpm-workspace.yaml`.

## API-03 — next (to be defined)

`src/modules/<domain>/` layout, `/api/v1` routing, DTO validation, OpenAPI decorators, the e2e test pattern
(`test/app.e2e.spec.ts`). Needed before the first model is **used**: a PostgreSQL environment (see "Deferred").

Likely candidates, in the order of the Data Foundation: DATA-1 canonical models (Experience, Place, Event, Location,
Pricing, Source metadata — `appdocs/domain/`), then the first Prisma models and repositories. Open product decisions that
affect the schema are listed in `appdocs/DOCUMENTATION_RESTRUCTURE_REPORT.md` ("Decisions needed").
